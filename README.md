# signals-core

Библиотека классов с предметной логикой генерации и обработки сигналов. Не зависит от пользовательского интерфейса и собирается самостоятельно, без приложения.

## Состав проектов

- `SignalProcessing.Core` — библиотека классов (.NET Framework 4.8), содержащая логику работы с сигналами.
- `SignalProcessing.Core.Tests` — модульные тесты библиотеки на xUnit 2.x (.NET Framework 4.8).

## Требования

- .NET Framework 4.8
- Пакет ScottPlot в этом репозитории **не используется** — библиотека не зависит от средств построения графиков и WPF.

## Состав библиотеки

- `SingleChannelSignal` — одноканальный сигнал: хранит частоту квантования (`Frequency`) и массив отсчётов (`Data`), вычисляет отметки времени.
- `SingleChannelSignalWriter` — сохранение сигнала в файл (`Write`).
- `SingleChannelSignalReader` — загрузка сигнала из файла (`Read`).
- `SignalOperations` — операции над сигналами: поэлементная сумма (`Sum`) и последовательная склейка (`Concat`).
- `OfflineFilter` — пакетная (офлайн) фильтрация массива отсчётов скользящим средним.
- `OnlineFilter` — потоковая (онлайн) фильтрация скользящим средним: использует циклический буфер и скользящую сумму, поддерживает `Reset`.
- `OfflineMedianFilter` — пакетная медианная фильтрация.
- `OnlineMedianFilter` — потоковая медианная фильтрация, поддерживает `Reset`.
- `ExponentialSmoothingFilter` — онлайн-фильтр экспоненциального сглаживания.
- `CircularBuffer<T>` — циклический буфер фиксированной ёмкости: хранит последние добавленные элементы, добавление выполняется за постоянное время.
- `Resampler` — пересчёт сигнала на новую частоту квантования линейной интерполяцией.
- `SingleChannelRangeAnalyzer` — анализ выхода значений сигнала за заданный диапазон.
- `ThresholdCutter` — ограничение значений сигнала по порогам.
- `Tools` — генераторы типовых сигналов: прямая, синусоида, белый шум.

## Формат файла сигнала

Текстовый файл: первая строка содержит частоту квантования в герцах, каждая следующая — одно значение сигнала. Дробная часть отделяется точкой независимо от языковых настроек системы: запись и чтение выполняются с `CultureInfo.InvariantCulture`.

## Запуск тестов

Тесты написаны на **xUnit 2.x**. Проект `SignalProcessing.Core.Tests` подключает три пакета через `PackageReference`:

| Пакет | Назначение |
| --- | --- |
| `xunit` | атрибуты тестов и класс `Assert` |
| `xunit.runner.visualstudio` | запуск тестов из Visual Studio |
| `Microsoft.NET.Test.Sdk` | инфраструктура запуска тестов |

Пакеты `xunit.v3` не используются: третья версия xUnit не поддерживает проекты, созданные по шаблону Class Library (.NET Framework).

Порядок запуска в Visual Studio:

1. Открыть решение `SignalProcessing.Core.sln`.
2. Восстановить пакеты NuGet (выполняется автоматически при первой сборке).
3. Собрать решение: **Build ? Build Solution**.
4. Открыть окно тестов: **Test ? Test Explorer**.
5. Нажать **Run All Tests**.

Пройденные тесты отмечаются зелёным, не пройденные — красным; при выборе теста внизу окна выводится ожидаемое и фактическое значение. Отдельный тест запускается из контекстного меню в Test Explorer или по значку рядом с методом в редакторе; там же доступен запуск теста под отладчиком (**Debug**).

## Связанные репозитории

Библиотеку использует приложение из репозитория https://github.com/no3umuB37/signals-generator-app

Библиотека **собирается самостоятельно**, наличие приложения для её сборки не требуется.

Оба репозитория клонируются в один родительский каталог, рядом друг с другом, под своими именами:

```
D:\<рабочий каталог>
??? signals-core
??? signals-generator-app
```

Решение `SignalGenerator.sln` приложения ссылается на проект библиотеки по относительному пути `..\signals-core\SignalProcessing.Core`, поэтому имена каталогов и их расположение изменять нельзя — иначе решение приложения не откроется.
